# Legal notes

- Engine/game code: GPLv2 (derived from id Software's Quake II source release). This project is GPLv2.
- No game data is committed. Nothing derived from pak files (parsed lumps, textures, fixture outputs) is committed;
  only hashes (`fixtures/MANIFEST.sha256`) and synthetic fixtures made from scratch.
- The demo archive is downloaded unmodified from a mirror and verified by sha256 (`tools/demo.sha256`).
- Retail/CTF paks are user uploads; assets derived from them are served only to the uploading account
  (and to players who own a pak with identical content hashes).
- AI agent (docs/AGENT.md, ADR-0006):
  - Demos and traces reference the game's assets and map strings: a `.dm2` holds the server's messages
    (configstrings with the map name and title, model, sound and image names, entity and player states), and
    traces and `run.json` name maps, monster and item classes and quote HUD/level strings. They contain no asset
    content (no BSP, texture, model or sound data). Nav graphs and `q2nav dump` files are computed from the maps'
    BSP and entity lumps.
  - None of that is committed: run directories (`runs/`, `server/runs/`, `data/bots/`) and the nav cache
    (`assets/nav/`) are ignored. CI uploads them only as short-lived workflow artifacts.
  - Scope: bots play the free demo pakset (`q2server` runs them on the demo pakset only; `q2bot` reads the demo
    pak by default). A bot's artifacts are served only to the accounts that may see the bot (its owner,
    administrators, anyone for a public bot).
  - Committed agent fixtures (docs/FIXTURES.md): the route tables `fixtures/agent/routes/*.json` are hand-written
    facts about the demo maps (entity indexes, inline model numbers such as `*34`, targetnames, classnames,
    coordinates). `fixtures/agent/demo1-walker-10s{,.record-header}.dm2` are Go-server recordings of 10 s on the
    demo's demo1 (27 KB and 8 KB: names and states as above, no asset content). They are the one exception to "nothing derived from
    pak files": the TypeScript header-parity test needs a recording written by the Go recorder, and the files are
    regenerated byte for byte from the demo pak. The decide/jev goldens are synthetic lane states.
  - `q2bot jev-probe` and the jev backend send lane states (text: classes, buckets, bearings, distances) to the
    Jev API; no game data and no personal data goes to the model, and the API key stays on the server.
