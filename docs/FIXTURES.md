# Golden fixture contract

Fixtures are produced by the C oracle (`oracle/`) and consumed by Go (`go test -tags golden`) and
TypeScript (vitest) tests. Inputs live in `fixtures/scenarios/` (committed); outputs in
`fixtures/generated/` (gitignored, regenerated by `make fixtures`, hashes in `fixtures/MANIFEST.sha256`).
Tests locate outputs via env `Q2_FIXTURES` (default `<repo>/fixtures/generated`) and game data via
`Q2_BASEDIR` (default `<repo>/assets/demo`, containing `baseq2/pak0.pak`). Tests **skip** (not fail)
when fixtures or data are absent.

## Encoding rules
- JSON Lines (`.jsonl`): one JSON object per line. Plain JSON (`.json`) for single records.
- C `float` values are printed with `%.9g` (round-trips float32 exactly). Consumers parse as float64 and
  narrow: Go `float32(v)`, TS `Math.fround(v)`. Comparison is exact (bitwise) unless `spec/tolerances.json`
  says otherwise.
- C `double` values: `%.17g`. Integers: decimal. Byte buffers: lowercase hex string.
- Vectors: arrays of 3 numbers. `short[3]`: arrays of 3 integers.
- Maps are referenced by name (`demo1`), loaded from `maps/<name>.bsp` inside the pak.

## core/bsp/<map>.json  (oracle_core bsp)
```
{ "map":"demo1", "checksum": <int, CM_LoadMap checksum as unsigned 32-bit>,
  "numclusters":N, "numareas":N, "numleafs":N, "numnodes":N, "numplanes":N, "numbrushes":N,
  "numbrushsides":N, "numleafbrushes":N, "numtexinfo":N, "numareaportals":N, "numcmodels":N,
  "entitystring_sha256":"...",
  "cmodels":[{"mins":[..],"maxs":[..],"origin":[..],"headnode":N}],
  "pvs":["<hex of CM_ClusterPVS row, (numclusters+7)>>3 bytes>", ...],   // per cluster
  "phs":["<hex>", ...],
  "leafs":[{"contents":N,"cluster":N,"area":N}]                              // per leaf
}
```

## core/trace/<map>.jsonl  (oracle_core trace)
One line per query:
```
{"q":{"kind":"box"|"transformed"|"point"|"pointt"|"leaf",
      "start":[..],"end":[..],"mins":[..],"maxs":[..],"headnode":N,"mask":N,
      "origin":[..],"angles":[..], "p":[..]},
 "r":{"allsolid":0|1,"startsolid":0|1,"fraction":f,"endpos":[..],
      "plane":{"normal":[..],"dist":f,"type":N,"signbits":N},
      "surface":{"name":"...","flags":N,"value":N},"contents":N}}
```
`box`: CM_BoxTrace(start,end,mins,maxs,headnode,mask). `transformed`: CM_TransformedBoxTrace(..., origin, angles).
`point`: `r = {"contents": CM_PointContents(p, headnode)}`. `pointt`: CM_TransformedPointContents(p,headnode,origin,angles).
`leaf`: `r = {"leaf": CM_PointLeafnum(p)}`. When the trace hits nothing, `surface` is the null surface (`name:""`).
`q` carries only the fields its kind uses: box `start,end,mins,maxs,headnode,mask`; transformed adds `origin,angles`;
point `p,headnode`; pointt `p,headnode,origin,angles`; leaf `p`. `headnode` 0 is the world, otherwise the headnode of
an inline model (`cmodels[i].headnode`). Each map file has ~20000 queries (hand-written edge cases first, then a
seeded random mix); generated by `oracle_core trace <map> --random 20000 --seed S`.

## core/pmove/<scenario>.jsonl  (oracle_core pmove)
First line: `{"header":{"map":"demo1","airaccelerate":f}}`. Then one line per usercmd:
```
{"cmd":{"msec":N,"buttons":N,"angles":[s,s,s],"forwardmove":N,"sidemove":N,"upmove":N,"impulse":N,"lightlevel":N},
 "in":{ pmove_state (only on the first step and whenever the scenario resets state) },
 "out":{"s":{"pm_type":N,"origin":[s,s,s],"velocity":[s,s,s],"pm_flags":N,"pm_time":N,"gravity":N,"delta_angles":[s,s,s]},
        "viewangles":[..],"viewheight":f,"mins":[..],"maxs":[..],"groundentity":0|1,
        "watertype":N,"waterlevel":N,"numtouch":N}}
```
State is carried from step to step (`out.s` becomes the next input) unless an `in` is given. Trace callback:
`CM_BoxTrace(start, end, mins, maxs, 0, MASK_PLAYERSOLID)` (world only, like CL_PMTrace without entities),
and exactly like CL_PMTrace `trace.ent` is set to a non-NULL dummy when `fraction < 1` (Pmove needs a non-NULL
`ent` to stand on ground / record touches); `out.groundentity` is 1 when `pm.groundentity` is non-NULL.
pointcontents: `CM_PointContents(p, 0)`. `snapinitial` is false. The pmove state is fully reset (`memset` 0, then
`s`/`cmd`/callbacks) before every step. Fixtures: `demo1`, `demo2`, `demo3` (airaccelerate 0) and `demo1_airaccel`
(airaccelerate 10); their inputs are generated at fixture time into `generated/scenarios/pmove/` (derived from the map).

## core/msg/<kind>.jsonl  (oracle_core msg)
- `entity.jsonl`: `{"from":ES,"to":ES,"force":0|1,"newentity":0|1,"bytes":"<hex of MSG_WriteDeltaEntity>"}`
  where ES = `{"number","origin","angles","old_origin","modelindex","modelindex2","modelindex3","modelindex4","frame","skinnum","effects","renderfx","solid","sound","event"}`.
- `usercmd.jsonl`: `{"from":UC,"to":UC,"bytes":"<hex of MSG_WriteDeltaUsercmd>"}` (UC as in pmove `cmd`).
- `player.jsonl`: `{"from":PS|null,"to":PS,"bytes":"<hex>"}` using the body of SV_WritePlayerstateToClient
  (PS = pmove state + viewangles, viewoffset, kick_angles, gunangles, gunoffset, gunindex, gunframe, blend[4], fov, rdflags, stats[32]).
  Exact PS shape (also used by `game/`): `{"pmove":{"pm_type","origin","velocity","pm_flags","pm_time","gravity","delta_angles"},
  "viewangles":[..],"viewoffset":[..],"kick_angles":[..],"gunangles":[..],"gunoffset":[..],"gunindex":N,"gunframe":N,
  "blend":[f,f,f,f],"fov":f,"rdflags":N,"stats":[32 ints]}`. `from:null` means SV_WritePlayerstateToClient's `from == NULL` (zeroed dummy).
- `scalar.jsonl`: `{"op":"coord"|"angle"|"angle16"|"pos"|"dir"|"float"|"string"|"long"|"short"|"char"|"byte","v":<value>,"bytes":"<hex>"}`.
  `v` is a float (`%.9g`) for coord/angle/angle16/float, a vector for pos/dir, a string for string, an int for the
  integer ops (ints outside the type's range are included: the C writer truncates). `dir` with `"v":null` is `MSG_WriteDir(sb, NULL)`.
  Non-normalized dir vectors are included. Float inputs stay inside the range where the C float→int conversion is defined.
- `crc.jsonl`: `{"base":"<hex>","sequence":N,"crc":N}` for COM_BlockSequenceCRCByte; `{"block":"<hex>","crc16":N}` for CRC_Block.
- `md4.jsonl`: `{"block":"<hex>","checksum":N}` for Com_BlockChecksum (unsigned 32-bit).

## core/rand.json  (oracle_core rand)
`{"seed":1,"values":[... first 100000 values of rand() after srand(1) ...]}` plus `{"seed":12345,...}` in `rand-12345.json`.

## core/pak/<pak>.json  (oracle_core pak)
`{"files":[{"name":"...","filepos":N,"filelen":N,"sha256":"..."}]}` in directory order.

## game/<scenario>.jsonl  (oracle_game / oracle_game_ctf)
Scenario input (`fixtures/scenarios/game/<name>.json`):
```
{"map":"demo1","module":"baseq2"|"ctf","entstring_override":null|"...","seed":1,
 "cvars":{"skill":"1","deathmatch":"0","coop":"0","maxclients":"1",...},
 "clients":[{"userinfo":"\\name\\player\\skin\\male/grunt\\hand\\0\\fov\\90"}],
 "frames":600,
 "schedule":[{"frame":N,"client":0,"cmd":UC} | {"frame":N,"client":0,"command":"give all"} |
             {"frame":N,"client":0,"random_walk":{"seed":7,"until":600}}]}
```
Committed scenarios may use `"entstring_append":"<entities>"` instead of an inline override (the map's entity string
must not be committed). `oracle/scripts/prep_game_scenario.py` (run by `tools/gen-fixtures.sh`) materializes it into
`generated/scenarios/game/<name>.json`: `entstring_override` = the map's own entity string + the appended text, where
`$dmN` is replaced by the `origin` value of the N-th `info_player_deathmatch`; `entstring_append` is removed. With `"entstring_strip":["monster_",...]` (a list of classname
prefixes), the map's own entity blocks whose classname starts with one of the prefixes are dropped first (the key is
removed too; used by the `synth_*` scenarios so the map's own monsters do not interfere). The oracle
only reads the materialized form, and the output header echoes it.

Input semantics (in order, per frame N ≥ 1): schedule entries with `frame == N` in file order (`cmd` →
`SV_ClientThink`, only if the client is spawned; `command` → `SV_ExecuteUserCommand`, i.e. `new`/`begin`/... or
`ge->ClientCommand`; `random_walk` → starts a walk at frame N), then every active walk (frames `start <= N < until`,
default `until` = frames+1) in the order the walks were started. Random walk = one usercmd per frame from an
xorshift32 state (`x ^= x<<13; x ^= x>>17; x ^= x<<5`, 32-bit, seed 0 → 0x9E3779B9), `yaw`/`pitch` int16 starting at 0:
```
a = next(); b = next();
yaw = (short)(yaw + ((a & 0x3ff) - 512)); if (((a >> 10) & 31) == 0) yaw = (short)(yaw + 8192);
pitch = (short)(((a >> 16) & 0xfff) - 2048);
cmd = {msec:100, lightlevel:128, angles:[pitch, yaw, 0], impulse:0,
       forwardmove:[400,400,400,200,0,-200,400,400][b & 7], sidemove:[0,0,0,0,200,-200,400,-400][(b >> 3) & 7],
       upmove: u < 2 ? 200 : u == 2 ? -200 : 0  (u = (b >> 6) & 31),
       buttons: ((b >> 11) & 7) == 0 ? BUTTON_ATTACK|BUTTON_ANY : 0}
```
Consumers do not need to re-implement it: every input is echoed in the frame's `inputs` in application order (a
`cmd` for a client that is not `cs_spawned` is echoed but not applied; this does not happen in the committed scenarios).

Output: first line `{"header":{...scenario echo..., "edict_size":N, "edicts_encoding":"delta"|"full"}}`, then one line
per server frame, starting with frame 0:
```
{"frame":N,"level":{"framenum":N,"time":f,"killed_monsters":N,"total_monsters":N,"found_secrets":N,"total_secrets":N},
 "rand_calls":N,
 "inputs":[{"client":N,"cmd":UC} | {"client":N,"command":"..."}],
 "freed":[N,...],
 "edicts":[{"n":N,"classname":"...","s":ES,"solid":N,"svflags":N,"mins":[..],"maxs":[..],"health":N,
            "movetype":N,"flags":N,"nextthink":f,"velocity":[..],"avelocity":[..],"groundentity":N|-1,
            "enemy":N|-1,"owner":N|-1,"takedamage":N,"deadflag":N,"waterlevel":N,"spawnflags":N,
            "think":"<C function name or null>","aiflags":N|null,"currentmove":"<mmove name or null>"}],
 "clients":[{"ps":PS,"inventory":[256 ints],"health":N,"score":N,"weapon":"<classname>"|null}],
 "events":[{"t":"sound","ent":N,"channel":N,"sound":"<name>","volume":f,"attenuation":f,"timeofs":f} |
           {"t":"positioned_sound",...,"origin":[..]} |
           {"t":"configstring","index":N,"value":"..."} |
           {"t":"print","kind":"bprintf"|"cprintf"|"centerprintf"|"dprintf","ent":N|-1,"level":N,"text":"..."} |
           {"t":"multicast","origin":[..],"to":N,"bytes":"<hex>"} | {"t":"unicast","ent":N,"reliable":0|1,"bytes":"<hex>"} |
           {"t":"cmd","text":"..."}]}
```
Only `inuse` edicts are listed. Function names are resolved from the game module's symbol table (`dladdr`)
so fixtures name callbacks exactly as the Go registry does. `rand_calls` counts `rand()` calls made during the frame.

Details (normative):
- **Frame 0** is the state right after `srand(seed)`, `SV_SpawnServer` (SpawnEntities + 2 `RunFrame`) and the
  connection of every scenario client (ClientConnect → ClientUserinfoChanged → `new` → `begin`, i.e. ClientBegin), in
  client order. Its `rand_calls`/`events` cover all of that. Frames 1..`frames` are one server frame each:
  inputs, `sv.framenum++`, `sv.time = sv.framenum*100`, `ge->RunFrame()`, dump, then `SV_PrepWorldFrame` (clears
  every `s.event`, as the engine does at the end of SV_Frame). `level.framenum` is therefore `frame + 2`.
- **Delta encoding** (`edicts_encoding:"delta"`, the default; the oracle's `--full` gives `"full"`): frame 0 lists every
  inuse edict. Later frames list only edicts whose record differs from the previous frame (including edicts that
  became inuse); `freed` lists edicts that were inuse in the previous frame and are not now. The full edict list of
  frame N = list of frame N-1, minus `freed`, with listed records replacing/adding by `n`. With `"full"`, `freed` is
  still emitted and every inuse edict is listed each frame. (Full dumps would be ~200 KB per frame.)
- `aiflags`/`currentmove` are only emitted (non-null) for edicts with `SVF_MONSTER` in `svflags`.
  `think`/`currentmove` are exact symbol names (static functions included, from `.symtab`); an address that is not a
  symbol start would be written `"?+0x<offset>"` (never seen in the committed scenarios).
- `clients`: one entry per scenario client, in scenario order (`null` if that slot has no `gclient_t`). `health` is the
  client's edict `health` (live value; `pers.health` is only updated on level changes), `score` = `resp.score`,
  `weapon` = `pers.weapon->classname`, `inventory` = `pers.inventory`.
- Events are in call order. `ent` is the edict number or -1 for NULL. `print.level` is the print level for
  bprintf/cprintf and 0 for dprintf/centerprintf; text is the fully formatted string. `sound`/`positioned_sound`
  name the sound by its configstring (`CS_SOUNDS+index`); `positioned_sound.origin` and `multicast.origin` may be null.
  `multicast`/`unicast` bytes are the contents of `sv.multicast` at the call. Configstring writes done by the engine
  itself (e.g. `gi.modelindex` registering a new name after spawn) are not events; `gi.configstring` calls are.
  `cmd` events (`gi.AddCommandString`) are recorded and **not executed** (no map change, no `menu_loadgame`).
- Engine differences from a live server (see docs/ORACLE.md): no networking, client pings are 0, userinfo gets
  `\ip\loopback`, `SV_Frame`'s per-frame `rand()` is not called, and the rand stream is reset with `srand(seed)`
  after `SV_InitGame` (so SV_InitGame's `svs.spawncount = rand()` is not part of the stream).

## fixtures/agent (committed; the AI agent, docs/AGENT.md)

These are not produced by the C oracle and are not covered by `fixtures/MANIFEST.sha256`.

### demo1-walker-10s.dm2, demo1-walker-10s.record-header.dm2
- `demo1-walker-10s.dm2` is the `server/internal/demo` Recorder's output for a seeded lockstep walker on demo1
  (seed 1, skill 1, 100 server frames): the server messages exactly as the client received them, in the
  `CL_Record_f`/`CL_WriteDemoMessage` client format, with `Writer.AllBaselines` (see PARITY TODO-IMPROVE).
- `demo1-walker-10s.record-header.dm2` is what `CL_Record_f` + `CL_Stop_f` write (exactly the C behaviour, no
  AllBaselines) for a client that played that recording up to its first frame: the reference of the
  TypeScript header-parity test.
- Consumers: `server/internal/demo` `TestFixtureDemo1Walker` (re-records both and requires them byte-identical:
  lockstep recording is deterministic) and `web/packages/q2-client/test/dm2-go.integration.test.ts` (plays the
  recording with the unchanged client's demo playback, then records right after the first frame and must write
  the header file byte for byte). Both skip without the demo pak, so CI runs `make demo` first.
- Regenerate (only when the recorder or the session legitimately changes):
  `cd server && Q2_UPDATE_FIXTURES=1 go test ./internal/demo -run TestFixtureDemo1Walker`.

### routes/ (route tables)
- `campaign.json` (the campaign: skill, start map, the visits in order, the terminal exit `victory.pcx`) and one
  hand-written table per visit: `demo1.json`, `demo2a.json`, `demo3.json`, `demo2b.json`. The schema, the step
  ops and the validation rules are in `fixtures/agent/routes/README.md`.
- Validated against the demo pak by `cd server && go run ./cmd/q2nav plan -pak ../assets/demo/baseq2/pak0.pak`
  (prints every exit's logic chains and each table's effects; exit 1 when a table is invalid) and in `go test` by
  `route.TestCheckedInTablesValid` and `cmd/q2nav` `TestPlanValidatesCheckedInTables`; `q2nav verify` also checks
  that every step is reachable on the nav graph. There is nothing to regenerate: edit the tables by hand and
  re-run `q2nav plan`.
